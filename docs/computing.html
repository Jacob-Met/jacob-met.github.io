CaptureSuite

I lead the architecture and direction of CaptureSuite. It runs a recording session across several devices and outputs one sealed package, instead of separate files from separate programs.

A daemon owns the clock and session state. Each device runs as a worker plugin in C++ or Python. There's a PySide6 operator UI, a simulator so it can be developed without hardware, and analysis jobs for quality checks and features.

The quality-check engine runs on a small synthetic session with no hardware if you want to try it.

Windows-only for now. The repository is the place for setup, licensing and current limits.

CanvasPilot

A lot of schools don't let students create Canvas API tokens, so I built CanvasPilot to use your normal login. You sign in once in a real browser (SSO and MFA work), and a small local broker makes API calls through that session. Cookies stay in the browser profile.

It covers courses, assignments, modules, files, discussions, the calendar and more, as a CLI and as an MCP server. Tests run on fixtures, and there's an offline demo that doesn't need a Canvas account.

Use it only where your school's policies allow. Submitting work and taking quizzes through it are real actions.

TowerOps

I made TowerOps for the AWS Agents for Humans challenge. It runs a synthetic scenario in which two aircraft are on a converging path. The agent can propose an advisory; it cannot issue a real clearance.

Before the simulated state changes, deterministic checks test the proposed action against the scenario and reject stale state. The demo then requires fixture approval and a matching acknowledgement, and records the result in a hash-chained audit log.

The public demo uses synthetic aircraft and fixture identities. There is no live aircraft feed, operational ATC integration or claim of aviation certification.

Research simulation only; not operational air-traffic-control software or a real clearance system.

uma-sim

uma-sim is my unofficial Rust engine for Umamusume's career mode: runs, events, races and scoring. It has a browser UI, a CLI, a REST API and an MCP wrapper.

Race physics is in its own clean-room crate. Tests and a calibration script check the numbers against the constants the engine loads.

Unofficial fan software with no connection to the game's creators, and it won't match every live-game mechanic.
